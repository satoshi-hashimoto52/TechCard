## 調査方法と情報源

## 事実と推測

コミット差分や資料から確認できる内容を事実として記載する。当時の意図、原因、テスト結果が履歴から確認できない場合は、断定せず「履歴から確認できない」または「推測」と明記する。テストコードの追加は、テスト成功の記録とは区別する。

## GitHub Issueとの対応

`issues/`配下の各ファイルは、GitHubへ登録したIssue本文である。Issue作成後は、本文末尾にIssue番号・URL・状態を追記する。対象タイトルと一致する既存Issue #1は重複作成せず本文と `retrospective` ラベルを反映し、候補2〜10を新規登録した。追加調査で対象機能と関連テストを確認できたため、#1〜#10をすべてクローズしている。

## 機密情報の扱い

証明書、画像、データベース、ログの内容はIssue本文へ転載していない。ローカル絶対パス、個人情報、認証情報、秘密鍵の内容も記載していない。
